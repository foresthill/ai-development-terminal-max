# CEF migration plan — macOS on Chromium, Windows/Linux on wry

作成: 2026-11-12 / ステータス: **計画（実機反復で段階実装）** / 背景: `CLAUDE.md` の vim 節、`spike/cef`（実証済み）

## ゴール
- **macOS ビルドだけ** webview エンジンを **CEF(Chromium)** にして、macOS 26 の WKWebView
  コンポジタバグ（wry#1848）を回避＝**vim 等の全画面 TUI を描画**させる。
- **Windows / Linux は現行 wry のまま**（バグが無く、Chromium 同梱の +170MB は不要）。
- フロント（xterm.js ＋ 既存 UI）は**そのまま**。記憶機能・UI 等の挙動は不変。

## 土台：Tauri 2.12 → 3.0-alpha
Tauri 3 はランタイムを **Cargo feature ではなくランタイム crate** で選ぶ。プラグインは全て
3.0-alpha あり（updater/dialog/clipboard-manager/process/opener）。`spike/cef` で
`tauri 3.0.0-alpha.6` ＋ `tauri-runtime-cef` が macOS で動作確認済み。

## プラットフォーム別ランタイム（肝）
`src-tauri/Cargo.toml`：
```toml
[dependencies]
tauri = "3.0.0-alpha"
# ... 共通 crate ...

[target.'cfg(target_os = "macos")'.dependencies]
tauri-runtime-cef = "3.0.0-alpha"

[target.'cfg(not(target_os = "macos"))'.dependencies]
tauri-runtime-wry = "3.0.0-alpha"
```
`src-tauri/src/main.rs`（CEF のサブプロセス入口は macOS のみ）：
```rust
#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]

#[cfg(target_os = "macos")]
#[tauri_runtime_cef::cef_entry_point]
fn main() { ai_dev_terminal_lib::run(); }

#[cfg(not(target_os = "macos"))]
fn main() { ai_dev_terminal_lib::run(); }
```
`src-tauri/src/lib.rs`（ランタイム選択）：
```rust
pub fn run() {
    let builder = tauri::Builder::default();
    #[cfg(target_os = "macos")]
    let builder = builder.runtime(tauri_runtime_cef::Cef::default());
    #[cfg(not(target_os = "macos"))]
    let builder = builder.runtime(tauri_runtime_wry::Wry::default());
    builder
        .plugin(/* ... 3.0-alpha plugins ... */)
        .manage(/* ... */)
        .invoke_handler(/* ... */)
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```
※ `.runtime()` の正確な型引数・ビルダー形は 3.0-alpha の API を実機で合わせる（spike で確認した形がベース）。`Builder::default()` の既定ランタイムと `.runtime()` 上書きの可否も要確認。だめなら `Builder::<Runtime>::new()` のジェネリック形に。

## プラグインの移行
`lib.rs` の各 `.plugin(tauri_plugin_*)` と `Cargo.toml` を 3.0-alpha へ：
- updater / dialog / clipboard-manager / process / opener → すべて `3.0.0-alpha`。
- 権限（capabilities）の自動生成が Tauri 3 で変わる（移行ガイドの "Plugin Autogenerated
  Permissions"）→ `src-tauri/capabilities/` を要調整。

## tauri.conf.json
- `app.macOSPrivateApi`：古い alpha は拒否した（spike での観測）。最新 alpha では正式フィールド。
  **CEF では vibrancy(NSVisualEffectView) の扱いが変わる**ので、macOS の見た目（現在の
  ソリッドダーク）を CEF で再確認し、不要なら外す。
- `$schema` を config/3 系に。`withGlobalTauri` 等は 3 でも有効（spike で確認）。
- CEF 署名用 entitlements は **CLI が自動付与**（Chromium 用）。既存の Apple 署名と整合するか要確認。

## CI（.github/workflows/release.yml）
- **macOS ジョブのみ**：CMake/Ninja 導入、**CEF 1GB の初回DL をキャッシュ**（`~/Library/Caches/tauri-cef`、`actions/cache`）、ビルド時間増。
- Windows/Linux ジョブは**無改変**（wry のまま）。
- tauri-action が Tauri 3 / CEF を理解するバージョンか要確認（だめなら手動 `tauri build`）。
- **成果物サイズ**：macOS の .app/.dmg と updater の `*.app.tar.gz` が **+170MB**。GitHub Releases/updater は可だが、updater のダウンロードが重くなる旨をリリースノートに明記。
- **署名/公証**：CEF の Frameworks（Chromium helper 群）も公証対象。Developer ID＋tauri-action で通るか、helper の個別署名が要るか要検証。

## 既存の DOM エディタ（Alt+E）
CEF 化で vim がターミナルで動くので**必須ではなくなる**が、フォールバックとして**残す**。

## リスク / 未知
- **Tauri 3 は alpha**：API 変更・不具合の可能性。production は本来 2.x 推奨なので、CEF 版は
  当面「macOS 実験的」位置づけで出すのが無難（必要なら feature フラグ的に）。
- **per-platform ランタイム**の実在性：cfg でランタイム crate を出し分ける構成が 3.0-alpha で
  素直に通るか（static dispatch）を最初のマイルストーンで確認。
- **公証**：Chromium 同梱アプリの notarization が追加作業になりうる。
- 全工程 **macOS 実機でのみ検証可**（この Linux 環境では CEF/署名/公証とも不可）。

## 段階実装（各ステップを Mac 実機ビルドで検証）
1. **ランタイム出し分けの骨組み**：Cargo.toml の per-target deps ＋ main.rs/lib.rs の cfg。
   まず**プラグイン無し相当で**ローカル `cargo tauri dev`（mac=CEF, win/linux=wry）が起動するか。
2. **プラグインを 3.0-alpha へ**：1つずつ戻して dev 起動を確認。capabilities 調整。
3. **tauri.conf / 見た目**：macOSPrivateApi・vibrancy を CEF 前提で確認・調整。
4. **ローカル release ビルド**（`pnpm tauri build`）で mac の vim 描画＆署名を確認。
5. **CI 改修**：macOS ジョブに CMake/Ninja＋CEFキャッシュ、サイズ/公証を確認。Win/Linux 不変。
6. **プレリリース**（例 v0.3.0-cef.1）で全OS成果物＋updater を実機確認 → 問題なければ本採用。

## ブランチ
`feature/cef-mac`（main から分岐）で段階実装。`spike/cef` は実証アーティファクトとして保存。
