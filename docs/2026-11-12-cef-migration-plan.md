# CEF migration plan — macOS on Chromium, Windows/Linux on wry

作成: 2026-11-12 / 更新: 2026-11-13 / ステータス: **ステップ1 成功（本体が macOS で CEF 起動＆vi 描画・dev）。残り：release/CI/Win・Linux 検証** / 背景: `CLAUDE.md` の vim 節、`spike/cef`（実証済み）

## ゴール
- **macOS ビルドだけ** webview エンジンを **CEF(Chromium)** にして、macOS 26 の WKWebView
  コンポジタバグ（wry#1848）を回避＝**vim 等の全画面 TUI を描画**させる。
- **Windows / Linux は現行 wry のまま**（バグが無く、Chromium 同梱の +170MB は不要）。
- フロント（xterm.js ＋ 既存 UI）は**そのまま**。記憶機能・UI 等の挙動は不変。

## 土台：Tauri 2.12 → 3.0-alpha
Tauri 3 はランタイムを **Cargo feature ではなくランタイム crate** で選ぶ。プラグインは全て
3.0-alpha あり（updater/dialog/clipboard-manager/process/opener）。`spike/cef` で
`tauri 3.0.0-alpha.6` ＋ `tauri-runtime-cef` が macOS で動作確認済み。

## プラットフォーム別ランタイム（肝）
`src-tauri/Cargo.toml`：
```toml
[dependencies]
tauri = "3.0.0-alpha"
# ... 共通 crate ...

[target.'cfg(target_os = "macos")'.dependencies]
tauri-runtime-cef = "3.0.0-alpha"

[target.'cfg(not(target_os = "macos"))'.dependencies]
tauri-runtime-wry = "3.0.0-alpha"
```
`src-tauri/src/main.rs`（CEF のサブプロセス入口は macOS のみ）：
```rust
#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]

#[cfg(target_os = "macos")]
#[tauri_runtime_cef::cef_entry_point]
fn main() { ai_dev_terminal_lib::run(); }

#[cfg(not(target_os = "macos"))]
fn main() { ai_dev_terminal_lib::run(); }
```
`src-tauri/src/lib.rs`（ランタイム選択）：
```rust
pub fn run() {
    let builder = tauri::Builder::default();
    #[cfg(target_os = "macos")]
    let builder = builder.runtime(tauri_runtime_cef::Cef::default());
    #[cfg(not(target_os = "macos"))]
    let builder = builder.runtime(tauri_runtime_wry::Wry::default());
    builder
        .plugin(/* ... 3.0-alpha plugins ... */)
        .manage(/* ... */)
        .invoke_handler(/* ... */)
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```
※ `.runtime()` の正確な型引数・ビルダー形は 3.0-alpha の API を実機で合わせる（spike で確認した形がベース）。`Builder::default()` の既定ランタイムと `.runtime()` 上書きの可否も要確認。だめなら `Builder::<Runtime>::new()` のジェネリック形に。

## プラグインの移行
`lib.rs` の各 `.plugin(tauri_plugin_*)` と `Cargo.toml` を 3.0-alpha へ：
- updater / dialog / clipboard-manager / process / opener → すべて `3.0.0-alpha`。
- 権限（capabilities）の自動生成が Tauri 3 で変わる（移行ガイドの "Plugin Autogenerated
  Permissions"）→ `src-tauri/capabilities/` を要調整。

## tauri.conf.json
- `app.macOSPrivateApi`：古い alpha は拒否した（spike での観測）。最新 alpha では正式フィールド。
  **CEF では vibrancy(NSVisualEffectView) の扱いが変わる**ので、macOS の見た目（現在の
  ソリッドダーク）を CEF で再確認し、不要なら外す。
- `$schema` を config/3 系に。`withGlobalTauri` 等は 3 でも有効（spike で確認）。
- CEF 署名用 entitlements は **CLI が自動付与**（Chromium 用）。既存の Apple 署名と整合するか要確認。

## CI（.github/workflows/release.yml）
**プレリリースで検証中（cef-mac のみ）。main の release.yml は無改変（＝Tauri 2・緑）。**

プレリリース実績：
- **v0.3.0-cef.1**：全ジョブ失敗。原因は **committed `Cargo.lock` が Tauri 2 のまま**（`tauri 2.12.5`）で、
  Cargo.toml / npm（Tauri 3-alpha）と不一致 → `tauri build` が "Found version mismatched Tauri packages" で
  即停止。ローカルは cargo が lock を自動再生成していたため露見しなかった。→ `cargo generate-lockfile` で
  lock を Tauri 3 に再生成してコミット（`cargo check --locked` 緑）。
- **v0.3.0-cef.2**：**Windows・Linux は SUCCESS**（Tauri 3 + wry、`tauri-action@v0` は Tauri 3-alpha CLI を
  問題なく駆動＝懸案1クリア）。macOS は macos-14 が t=0 cancel、macos-13 は starve。
- **v0.3.0-cef.3**：macOS を **arm64 単独**にしても `macos-14` が**単独でも t=0 cancel**（3回連続）。
  ＝**このアカウントは明示 arm64 ランナー（macos-14）を使えない**（entitlement/availability）。一方 Intel
  （macos-13）は cancel ではなく queue＝使える。過去の `macos-latest` 成功もこれと整合。

現構成（cef-mac、2026-11-14）：
- **macOS = Intel（`macos-13`, x86_64-apple-darwin, 1ジョブ）**。universal 不可＋arm64 ランナー不可のため
  x64 を CI でビルド。成果物 `…_x64.dmg`（Intel ネイティブ／Apple Silicon は Rosetta 2）＋ updater
  `darwin-x86_64`。**ネイティブ Apple Silicon（arm64）は M 系 Mac でローカルビルド**（`pnpm tauri build`）し、
  必要なら Release に手動添付。arm64 CI ランナーが使えるようになったら CI 化（公開リポの無料 arm64 枠や
  large runners、self-hosted mac 等）。
- **macOS ジョブに追加**：`brew install cmake ninja`（CEF の libcef_dll_wrapper ビルド）＋
  `actions/cache` で `~/Library/Caches/tauri-cef`（CEF ~1GB、キー `tauri-cef-<platform>-cef154.5.0`）。
- Windows/Linux ジョブは**無改変**（wry のまま）＝検証済み緑。
- **残る要検証（Intel CEF ビルドで判明する点）**：
  - CEF の Frameworks（Chromium helper 群）の署名/公証（Developer ID で通るか、helper 個別署名が要るか）。
  - macOS ランナーのディスク（CEF 1GB＋Chromium ビルド）が足りるか。
- **成果物サイズ**：macOS の .app/.dmg と updater の `*.app.tar.gz` が **+170MB**。リリースノートに明記済み。

## 既存の DOM エディタ（Alt+E）
CEF 化で vim がターミナルで動くので**必須ではなくなる**が、フォールバックとして**残す**。

## リスク / 未知
- **Tauri 3 は alpha**：API 変更・不具合の可能性。production は本来 2.x 推奨なので、CEF 版は
  当面「macOS 実験的」位置づけで出すのが無難（必要なら feature フラグ的に）。
- **per-platform ランタイム**の実在性：cfg でランタイム crate を出し分ける構成が 3.0-alpha で
  素直に通るか（static dispatch）を最初のマイルストーンで確認。
- **公証**：Chromium 同梱アプリの notarization が追加作業になりうる。
- 全工程 **macOS 実機でのみ検証可**（この Linux 環境では CEF/署名/公証とも不可）。

## 段階実装（各ステップを Mac 実機ビルドで検証）
1. ✅ **ランタイム出し分けの骨組み（完了 2026-11-13）**：Cargo.toml per-target deps ＋ main.rs/lib.rs の cfg。
   本体が **macOS で CEF 起動し、`vi` が描画・操作できた（dev ビルド、385MB）**。プラグイン(3.0-alpha)も問題なくビルド。
   ※注意：Tauri 3 化は全OS共通なので **Windows/Linux も Tauri 3(+wry) に移行済み＝CI で要再検証**。
2. **プラグインを 3.0-alpha へ**：1つずつ戻して dev 起動を確認。capabilities 調整。
3. **tauri.conf / 見た目**：macOSPrivateApi・vibrancy を CEF 前提で確認・調整。
4. **ローカル release ビルド**（`pnpm tauri build`）で mac の vim 描画＆署名を確認。
5. 🟡 **CI 改修（first cut 実装済み 2026-11-13・未検証）**：release.yml の macOS を arch 分割、
   CMake/Ninja＋CEFキャッシュ追加、リリースノートを arch 別 dmg に更新。上記「要検証」4点はプレリリースで確認。
6. **プレリリース**（例 v0.3.0-cef.1 を cef-mac のコミットにタグ）で全OS成果物＋updater を実機確認 → 緑なら
   main へマージ。**安全策（2026-11-13 ユーザー選択）**：main は Tauri 2・緑を維持し、CEF は本番グリーンを
   確認してから取り込む。skills / 設定2カラムは main 由来の独立ブランチで先行（CEF とは無関係）。
